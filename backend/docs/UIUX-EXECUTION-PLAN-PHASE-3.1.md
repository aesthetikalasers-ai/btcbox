# BTCBOX — Phase 3.1 全站视觉二次精修与布局比例优化执行方案
**基于**：Phase 3（分支 `feature/btcbox-premium-visual-system`，PR #10）之上继续打磨，**不是推翻重做**。
**执行原则**：在同一分支继续提交；禁止 push main、禁止生产部署；交易页布局锁定，结构性改动只提建议不实施；不动资金/认证/数据库核心逻辑。

## 本轮三个验收方向

### 方向一：视觉间距与布局（Spacing & Layout Audit）
- 审计页面区块之间、卡片之间、卡片内部（标题/数字/说明/按钮）的横向纵向间距统一性，避免过挤/过散/留白失衡。
- 页面内容宽度、左右边距、区块上下留白协调。
- **禁止**为统一而把所有页面做成同一种卡片堆叠——每页保留自身信息层级，设计语言一致。
- 优先：首页(/home)、市场(/markets)、资产(/assets)、订单(/orders)、个人中心(/me)。

### 方向二：交易页面空间合理性（Trade Page Space，布局锁定）
- 桌面端既有区域结构的宽度比例、对齐、信息密度、盘口与下单区视觉权重。
- 移动端左盘口/右下单/K线抽屉的空间利用。
- **允许**：尺寸、间距、对齐、字体、视觉层级、细节调整。
- **禁止**：改变区域结构/位置/操作流程。
- 若判断某区域比例需结构性调整，**只写优化建议，不擅自实施**。

### 方向三：全站多语言动态状态与提示一致性（i18n Dynamic State）
- 覆盖：系统通知/公告、操作反馈（成功/失败/处理中）、状态标签（待处理/审核中/已完成/已拒绝/已取消）、资金提示（充值确认/提现审核/到账/手续费）、交易提示（下单成功/取消/成交/部分成交/委托中）、表单验证、弹窗与 Toast、异常提示（网络错误/超时/服务不可用）。
- **动态更新**：页面打开期间切换语言，已渲染的通知/状态标签/提示必须立即更新（走 i18n hook 响应式，禁止一次性赋值或硬编码）。
- **数据与文案分离**：状态存储用稳定代码（pending/completed/rejected…），前端按当前语言映射显示；**禁止把本地化文本作为业务状态存储或比较键**。发现则列冲突清单，不擅自改业务逻辑。
- **历史记录同步**：充值/提现/订单/通知历史，切换语言后显示当前语言，而非创建时语言。
- 新增/补齐文案必须通过 `check:i18n`（8 语言包，vi 为 legacy）。语言菜单规范保持不变（默认日语、不跟随系统、7 语言固定顺序、/admin 固定中文）。

## 执行顺序
1. 确认在 `feature/btcbox-premium-visual-system` 分支，工作区干净。
2. 方向一间距审计与精修（优先页面）。
3. 方向二交易页空间精修（视觉/间距/比例，结构性建议写入报告）。
4. 方向三多语言动态状态审计与修复。
5. 响应式核查（桌面 1440×900 + 移动 390×844 截图）。
6. `npm run build` + `check:i18n` + e2e 如实报告。
7. 逐项验收报告 + 未完成事项 + 冲突清单 + PR 状态。
