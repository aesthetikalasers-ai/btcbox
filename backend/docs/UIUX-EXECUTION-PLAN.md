# BTCBOX — 第三阶段：全站视觉系统建设与 UI 精修执行方案

**项目名称：** BTCBOX  
**阶段名称：** Phase 3 — Premium Visual Design & UI Refinement  
**设计定位：** Premium Institutional Fintech  
**核心风格：** 深邃、专业、简洁、精致、可信赖  
**主品牌色：** Emerald Teal（翡翠青绿）  
**基础风格：** Dark Navy Financial Interface

---

# 一、项目目标

本阶段的目标不是简单地修改颜色、圆角或按钮，而是建立 BTCBOX 完整、统一、可长期维护的品牌视觉设计系统。

最终需要达到：

1. 全站拥有统一的品牌视觉识别。
2. 所有页面具有明确的视觉层级。
3. 桌面端和移动端采用一致的设计语言。
4. 交易、资产、管理后台、认证页面不再有拼接感。
5. 文字、数字、图标、卡片、表格、按钮拥有统一规范。
6. 重要操作突出，辅助信息简洁。
7. 用户可以快速识别重要数据、风险状态和操作结果。
8. 不影响已经完成的业务逻辑和后端功能。

**重要：本阶段属于视觉与交互表现优化，不是业务重构。**

# 三、第一阶段：建立全局 Design System

这是整个视觉改造最重要的基础。

先定义全局设计变量，不允许各页面自行随意定义颜色。

## Step 4：建立品牌颜色系统

### 4.1 品牌主色

| Token | 色值 | 用途 |
|---|---|---|
| Brand Primary | #21C7A8 | 品牌强调、主要操作 |
| Brand Hover | #13A98C | 鼠标悬停 |
| Brand Active | #0D806D | 按下状态 |
| Brand Soft | #102B27 | 品牌浅背景 |
| Brand Border | #1B6558 | 品牌强调边框 |

品牌青绿应该用于重要位置，而不是大面积铺满页面。

## Step 5：建立五级背景系统

| Token | 色值 | 用途 |
|---|---|---|
| Background 0 | #080D13 | 全站最底层背景 |
| Background 1 | #0D141D | 页面主内容背景 |
| Surface 1 | #131E29 | 普通卡片 |
| Surface 2 | #1B2936 | 弹窗、下拉菜单 |
| Surface 3 | #243443 | 悬停、选中区域 |

要求：

- 背景层级必须清楚。
- 不允许所有区域使用同一种黑色。
- 卡片之间通过颜色、边框和间距形成层次。
- 不要过度使用渐变。
- 不要让每张卡片都出现明显发光效果。

## Step 6：建立文字颜色系统

| Token | 色值 | 使用范围 |
|---|---|---|
| Text Primary | #F4F7FA | 页面标题、重要数字 |
| Text Secondary | #D5DEE7 | 普通正文、卡片标题 |
| Text Tertiary | #A2B0BE | 辅助说明 |
| Text Muted | #738293 | 时间、次要标签 |
| Text Disabled | #526170 | 禁用状态 |

文字必须有明确的阅读顺序。

## Step 7：建立金融数据颜色

| 状态 | 色值 | 用途 |
|---|---|---|
| Positive | #35D6A6 | 盈利、上涨、成功 |
| Negative | #F06B78 | 亏损、下跌、错误 |
| Warning | #E9B85C | 等待、审核、风险提醒 |
| Information | #72AEF2 | 信息提示 |
| Neutral | #A2B0BE | 普通状态 |

注意：

- 行情颜色必须遵循现有产品的涨跌规则。
- 资金操作成功与行情上涨不能混为同一个业务含义。
- 错误、警告、成功状态必须有文字或图标辅助，不能只依赖颜色。

## Step 8：建立边框和阴影系统

| Token | 建议值 | 用途 |
|---|---|---|
| Border Subtle | #202D39 | 普通分隔线 |
| Border Default | #263443 | 卡片边框 |
| Border Strong | #344657 | 强调边框 |
| Border Focus | #21C7A8 | 输入框聚焦 |
| Shadow Card | 轻微阴影 | 普通卡片 |
| Shadow Modal | 中等阴影 | 弹窗和浮层 |

阴影应该克制，不允许全站出现夸张的霓虹效果。

# 四、第二阶段：建立排版和空间系统

## Step 9：统一字体规范

建立全站统一字体体系。

建议：

- 英文与数字优先采用现代无衬线字体。
- 日文采用清晰易读的日文字体回退体系。
- 中文采用适当的系统字体回退。
- 数字使用稳定的数字排版，避免余额和价格跳动。

字体层级：

| 元素 | 建议字号 | 字重 |
|---|---:|---|
| 页面主标题 | 26–30px | 700 |
| 区域标题 | 18–22px | 600 |
| 卡片标题 | 15–17px | 600 |
| 正文 | 13–15px | 400 |
| 辅助文字 | 11–12px | 400 |
| 核心资产数字 | 28–36px | 600–700 |

注意：

不要所有文字都加粗。

重要数字、标题和普通说明必须形成明显区别。

## Step 10：统一间距系统

建立统一间距变量：

- 4px：极小间距
- 8px：图标与文字
- 12px：紧凑元素
- 16px：普通组件间距
- 20px：卡片内部间距
- 24px：内容区间距
- 32px：模块间距
- 40px：较大区域分隔
- 48px：页面主要区域间距

不要每个组件随意使用不同的间距。

## Step 11：统一圆角

建议：

| 元素 | 圆角 |
|---|---:|
| 小标签 | 4–6px |
| 输入框 | 8px |
| 普通按钮 | 8px |
| 普通卡片 | 12px |
| 大型内容卡 | 14–16px |
| 弹窗 | 16px |

不要所有东西都做成胶囊形。

# 五、第三阶段：建立全站公共组件

这一阶段先做组件，再修改页面。

## Step 12：按钮系统

建立四种标准按钮。

1. Primary Button：品牌青绿背景，深色文字。
2. Secondary Button：深蓝灰背景，浅色文字。
3. Outline Button：透明背景，边框强调。
4. Danger Button：危险操作红色。

每种按钮都必须支持：

- Default
- Hover
- Active
- Focus
- Disabled
- Loading

按钮要求：

- 高度统一。
- 字体和图标对齐。
- 加载状态不能造成布局跳动。
- 提交成功后有明确反馈。
- 防止重复提交。
- 危险操作需要明确提示。

## Step 13：输入框系统

统一：

- 输入框高度
- 背景色
- 边框颜色
- 圆角
- Placeholder
- Focus 状态
- Error 状态
- Disabled 状态

错误提示应该放在输入框附近，不要只弹出一个 Toast。

## Step 14：卡片系统

建立：

- 普通信息卡
- 资产卡
- 统计卡
- 订单卡
- 状态卡
- 功能卡

统一：

- 背景层级
- 边框
- 圆角
- 内边距
- 标题与内容间距
- 数字展示规范

## Step 15：弹窗与反馈系统

统一：

- Modal
- Confirm Dialog
- Success Toast
- Error Toast
- Warning Toast
- Loading Overlay
- Dropdown
- Tooltip

所有操作都要有明确反馈。

不得出现点击后没有任何响应的按钮。

## Step 16：表格系统

重点优化管理后台和交易记录：

- 表头与正文形成层级。
- 金额右对齐。
- 数字使用统一格式。
- 行高统一。
- Hover 状态清楚。
- 状态标签统一。
- 空数据状态完整。
- 手机端提供合理的响应式布局。

# 六、第四阶段：逐页面视觉精修

公共组件完成并通过检查后，才开始逐页面改造。

## Step 17：交易页面

这是 BTCBOX 最重要的页面。

**交易页面布局已经锁定，不允许擅自重新设计。**

允许：

- 优化文字层级。
- 优化颜色。
- 优化边框。
- 优化图标。
- 优化按钮视觉。
- 优化数字排版。
- 优化状态提示。
- 优化细微交互反馈。

禁止：

- 改变交易区域布局。
- 改变盘口与下单区域的位置。
- 擅自改变 K 线区域结构。
- 改变桌面端既定布局。
- 改变手机端左盘口、右下单及 K 线抽屉结构。
- 影响交易操作流程。

特别检查：

- 币种 Logo 是否稳定。
- 行情更新是否闪烁。
- 价格变化是否引起页面跳动。
- 买入和卖出是否容易区分。
- 下单按钮是否突出。
- 数字是否容易阅读。

## Step 18：用户资产中心

重点：

- 总资产数字突出。
- 可用余额和冻结余额清晰区分。
- 充值、提现操作容易找到。
- 资产明细层级清楚。
- 资金记录容易查看。
- 不要使用过多说明文字。

## Step 19：充值页面

重点：

- 充值金额输入突出。
- 网络和币种信息清晰。
- 地址和二维码区域整洁。
- 复制按钮明显。
- 风险提醒清楚。
- 充值状态明确。
- 防止用户误选网络。

不得改变充值业务规则。

## Step 20：提现页面

重点：

- 可提现余额清晰。
- 提现地址、金额和网络层级清楚。
- 手续费和到账金额分开显示。
- 风险提醒明显。
- 确认操作有二次确认。
- 审核中、成功、失败状态统一。

不得改变资金审核和扣款逻辑。

## Step 21：登录和注册页面

重点：

- 统一品牌风格。
- 减少无意义文字。
- 输入区域清晰。
- Google 登录按钮视觉统一。
- 登录和注册之间切换自然。
- 错误提示准确。
- 加载状态明确。
- 不要让注册成功后又意外跳回注册页面。
- 保持用户会话和认证状态正确。

## Step 22：个人中心

重点：

- 用户信息清楚。
- 账户安全入口明确。
- 资产和记录容易找到。
- 页面层级简单。
- 不要让所有功能挤在一个区域。

## Step 23：管理后台

重点：

- 数据表格清晰。
- 统计数字突出。
- 用户和权限信息易读。
- 审核操作突出。
- 危险操作有明显警告。
- 超级管理员和普通管理员的权限展示清楚。

管理后台不能只追求美观，必须保证操作准确。

## Step 24：客服和帮助中心

重点：

- 信息结构清楚。
- FAQ 分类明确。
- 聊天窗口整洁。
- 用户消息与客服消息明显区分。
- 空状态、等待状态、错误状态统一。

# 九、开发与合并规则

1. 视觉修改必须在独立分支完成。
2. 先完成公共 Design System，再逐页使用。
3. 不允许各页面重复创建不同的颜色体系。
4. 不允许为了视觉效果删除已有业务信息。
5. 不允许修改数据库、资金逻辑及认证核心流程。
6. 不允许修改已锁定的交易页面布局。
7. 每完成一个主要模块，提交对应 Commit SHA。
8. 保留修改前后截图。
9. 在 Preview 环境进行视觉和浏览器验收。
10. 所有测试通过后再提交 PR。
11. 未经批准不得合并生产分支或部署生产环境。

# 十一、最终验收标准

BTCBOX 必须达到以下产品标准：

**品牌层面：**
具有明确的品牌辨识度，而不是普通的加密货币模板。

**视觉层面：**
颜色、字体、间距、图标、卡片具有统一规范。

**信息层面：**
重要信息突出，辅助信息简洁，阅读顺序明确。

**交互层面：**
所有操作有反馈，用户不会不知道系统正在做什么。

**响应式层面：**
桌面端和手机端都保持专业、整洁和稳定。

**业务层面：**
所有原有业务功能和交易页面布局完整保留。

**工程层面：**
组件可复用，颜色可维护，页面不能各自为政。

# 十二、执行顺序与授权边界

请严格按照以下顺序执行：

第一步：确认第二轮业务修复及前后端整合已经验收。

第二步：建立独立视觉分支。

第三步：建立完整 Design System。

第四步：完成公共 UI 组件。

第五步：逐页面进行视觉精修。

第六步：完成桌面端和移动端适配。

第七步：完成浏览器回归测试。

第八步：提交 PR，等待最终验收。

**执行原则：**

已经明确授权的视觉范围内，可以批量推进，不需要每修改一个按钮就等待审批。

但是，涉及交易布局、资金逻辑、认证核心流程、数据库、公共业务规范和生产部署的修改，必须遵守原有审批边界。

**最终目标：将 BTCBOX 打造成具有统一品牌语言、专业金融产品质感、清晰信息层级和稳定操作体验的完整交易平台。**

# 十三、BTCBOX 全站 UI 视觉设计与验收规范 V1.0（正式验收基准）

**规范状态：正式定稿**  
**适用范围：BTCBOX 后续全部新页面开发、旧页面重构、组件整合、视觉修改及上线前检查。**  
**执行要求：本章为强制验收标准；四层验收必须同时通过，任何一层未通过，不得将页面标记为最终验收通过。**

## 13.1 四层验收体系

| 层级 | 验收内容 | 必须通过 |
|---|---|---|
| 第一层 | 全站视觉一致性 | ✓ |
| 第二层 | 手机端独立验收 | ✓ |
| 第三层 | 电脑端独立验收 | ✓ |
| 第四层 | 连续响应式验收 | ✓ |

四层必须同时通过，不能互相替代。全站一致性检查不能代替手机端或电脑端独立检查；固定宽度测试也不能代替断点之间的连续响应式检查。

## 13.2 正式设备测试规格

| 设备类别 | 测试视口宽度 |
|---|---:|
| 手机小屏 | 375px |
| 手机标准屏 | 390px |
| 手机大屏 | 430px |
| 平板 | 768px |
| 笔记本 | 1366px |
| 桌面显示器 | 1440px |
| 大屏显示器 | 1920px |

除以上七个固定宽度外，必须检查断点之间的连续变化，重点观察布局切换、卡片宽度、间距、文字换行、导航变化和内容溢出，不得只验证固定断点。

## 13.3 统一设计参数

| 项目 | 设计基准 |
|---|---|
| 手机端参考范围 | 320–430px |
| 平板端参考范围 | 600–899px |
| 桌面端参考范围 | 900px 以上 |
| 卡片圆角 | 12–16px |
| 卡片内边距 | 16–20px |
| 按钮高度 | 44–48px |

以上为统一设计基准，不是所有组件必须机械套用的固定值。实际页面应根据功能、内容密度、信息层级和可用空间合理调整。卡片尺寸、宽高比例和排列方式应服务于内容及操作，不要求所有卡片一律等大或等高。

## 13.4 页面验收状态定义

- **通过：** 视觉、布局、交互及响应式表现均符合规范。
- **待修复：** 存在间距、对齐、层级或适配问题，但尚未造成关键操作受阻；修复并复测前不得最终通过。
- **未通过：** 存在横向溢出、内容遮挡、严重错位、关键内容不可读或操作受到影响等问题。

## 13.5 每页必须保留的验收证据

每个完成修改的页面必须保留：

1. 手机端检查结果及截图。
2. 电脑端检查结果及截图。
3. 全站视觉一致性检查结果。
4. 连续响应式检查结果，记录测试宽度及断点间检查情况。
5. 发现的问题、修复记录及复测结果。

截图和报告必须对应实际测试结果，不得以计划、推测或单一设备截图代替验收证据。未实际执行的项目应标记为未测试，不得标记通过。

## 13.6 手机端独立验收项目

- 检查横向溢出及页面宽度。
- 检查单列、双列或其他布局是否符合内容和操作需求。
- 检查字体大小、行高、长文本换行及数字截断。
- 检查按钮和触控区域是否易于操作。
- 检查图片比例、裁切和清晰度。
- 检查卡片之间、页面边缘及模块内部间距。
- 检查顶部导航、底部菜单及安全区域是否遮挡内容。
- 检查弹窗、下拉菜单、表格、图表和键盘弹出时的适配。

## 13.7 电脑端独立验收项目

- 检查内容最大宽度及页面整体居中/对齐。
- 检查多列卡片的对齐、宽高比例及横纵间距。
- 检查侧边导航与主内容区域的比例和协调性。
- 检查空白空间利用，避免内容过度拉伸或拥挤。
- 检查大屏下卡片、表格、图表和模块的可读性。
- 检查标题、正文、数字、图标及操作按钮的层级和对齐。

## 13.8 全站视觉一致性验收项目

统一检查卡片间距、页面边距、卡片内边距、圆角、边框、阴影、字体及颜色、图标风格、按钮尺寸、模块间距，以及通知、成功、错误、警告和状态提示的表现。相同语义和相同用途的组件应保持一致；不同功能组件允许在统一设计系统内作合理差异化。

## 13.9 交易页面特别保护规则

交易页面遵循：**保护交易操作逻辑和核心操作关系，允许全面优化界面设计与交互体验。**

- 不擅自改变下单、撤单和交易流程及其业务含义。
- 不破坏行情、盘口、K 线及交易数据流程。
- 保留现有交易功能分区和核心操作关系。
- 允许根据实际使用体验优化盘口、下单区、K 线和订单区的宽高比例、间距、对齐、字体、颜色、视觉层次及响应式布局。
- 桌面端和手机端均须独立验收；不得将旧有布局限制理解为禁止一切布局比例优化。
- 每次涉及交易页面的修改，都必须复测关键交易操作及数据展示。

## 13.10 最终完成标准

页面只有同时满足以下全部条件，才可标记为最终验收通过：

1. 功能正常。
2. 全站视觉一致性通过。
3. 手机端独立验收通过。
4. 电脑端独立验收通过。
5. 连续响应式验收通过。
6. 交易核心操作及相关数据流程未受影响。
7. 多语言排版经过验证，语言切换后的文字、通知、状态、按钮及布局均正确。

任何一项未通过或尚未实际验证，都不得标记为最终验收通过。

## 13.11 与本文旧条款的衔接及优先级

本 V1.0 规范是本文后续全部视觉开发、页面修改、组件整合及最终验收的统一强制基准。若本文前文旧条款与本章发生冲突，以本章为准。

特别是交易页面：前文关于“布局已经锁定”及禁止调整布局的表述，应解释为保护交易功能、核心操作关系和既有业务流程，不得据此禁止经评估后对区域宽高比例、间距、对齐和响应式表现进行合理优化；任何此类优化均须遵守本章交易页面特别保护规则并完成关键操作复测。

本规范纳入每次页面修改的开发检查、PR 验收和上线前检查流程。未经实际测试并留存证据，不得宣称通过；未经授权不得因此直接合并生产分支或部署生产环境。
