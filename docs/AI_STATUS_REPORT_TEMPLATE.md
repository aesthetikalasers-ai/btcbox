# BTCBOX — 统一进度汇报格式

**适用范围：** 所有参与 BTCBOX 的 AI、开发人员、数据库负责人和项目协调负责人。  
**强制要求：** 开始任务、完成任务、遇到阻塞、阶段验收和跨成员/跨会话交接时，均使用本格式。  
**状态词：** PASS（有证据通过）/ NEEDS FIX（发现问题需修复）/ NOT VERIFIED（尚未验证或缺少条件）。

## 汇报纪律

1. 不得只写“已完成”“正在处理”“没有问题”等无法核实的结论。
2. 未实际执行的测试必须标记 **NOT VERIFIED**，不得推测为通过。
3. 未产生提交时写“未提交”，不得编造 Commit SHA；提交必须提供完整 SHA 和分支。
4. 构建通过不等于业务功能通过；局部测试通过不等于整个阶段通过。
5. 阶段退出条件未全部满足时，状态不得写“已通过”，也不得擅自进入下一阶段。
6. 重要进度、阶段完成、负责人变化、阻塞和交接后，必须同步更新 `docs/AI_PROJECT_STATE.md`。
7. 所有 AI 和负责人使用同一格式，不因角色不同而豁免。
8. 汇报中的文件、分支、SHA、测试和证据必须可复核；没有证据的内容明确标记 NOT VERIFIED。

**汇报目标：** 任何接手者都能立即看清项目当前在哪里、实际完成了什么、证据是什么、还缺什么，以及下一步唯一优先事项。
