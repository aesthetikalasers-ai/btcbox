# BTCBOX 全站 UI 视觉设计与验收规范 V1.0

> 本规范是 BTCBOX 后续所有页面开发、修改、重构、组件整合及发布前验收的共同标准。页面能够正常显示或功能可运行，不代表视觉验收完成。

## 1. 总体原则

1. 全站视觉一致性、手机端独立验收、电脑端独立验收、连续响应式验收是四个独立层次，**必须同时通过**，不得相互替代。
2. 设计规格、代码实现、实际视觉效果和最终验收是不同阶段。规格已定义不代表页面已实现，更不代表已经验收。
3. 每个页面都必须有独立的检查结果和可复核证据；没有实际测试和证据，不得标记为最终通过。
4. 视觉精修应兼顾空间比例、视觉层次、可读性、一致性和真实操作体验，不以简单整齐或元素能够显示作为完成标准。
5. 卡片不必全部采用相同尺寸，应根据内容、功能重要性和所在区域确定尺寸，但同类组件的视觉规则应保持一致。

## 2. 四层验收体系

### 第一层：全站视觉一致性

检查全站共用的设计语言和组件规则：

- 卡片间距、圆角、阴影及边框。
- 字体、字号、字重、颜色和图标。
- 页面边距、模块间距和内容密度。
- 按钮、输入框、通知、徽标及状态提示。
- 同类组件的状态、交互反馈和视觉层次。
- 不同页面之间的组件样式与间距一致性。

全站一致性检查不能代替任何设备端独立检查。

### 第二层：手机端独立验收

手机端设计范围：**320–430px**。

逐页检查：

- 单列、双列布局是否符合内容和操作场景。
- 卡片宽度、间距、内部留白和内容顺序。
- 文字可读性、换行、截断及长内容处理。
- 触控目标尺寸和操作间距。
- 顶部/底部导航、系统安全区域及固定元素。
- 弹窗、抽屉、下拉菜单和键盘出现时的布局。
- 图片、图表和表格的缩放、滚动及信息可读性。
- 是否存在横向溢出、内容遮挡或操作区域被覆盖。

不得仅通过缩小桌面页面来判断手机端合格；手机端必须作为独立布局进行设计检查和实际测试。

### 第三层：电脑端独立验收

电脑端设计范围：**900px 以上**。

逐页检查：

- 多栏布局、栏宽和主次区域比例。
- 页面及内容最大宽度。
- 卡片高度、间距、边缘和基线对齐。
- 导航区与主内容区的关系。
- 图表、表格、行情、盘口及操作区的空间分配。
- 信息密度、留白和视觉层次。
- 大屏幕空间利用率，避免内容过度拉伸或无意义留白。
- 弹窗、下拉菜单、悬浮层和固定区域是否遮挡内容。

电脑端必须独立检查，不能以手机端测试结果代替。

### 第四层：连续响应式验收

- 除固定测试尺寸外，还要检查断点之间的连续变化。
- 检查布局切换、列数变化、卡片宽度和间距变化是否平滑合理。
- 防止卡片突然变形、错位、挤压、重叠或内容跳动。
- 在断点附近重点检查布局稳定性。
- 确保手机、平板、桌面之间的过渡不影响阅读和操作。

## 3. 设计断点与基础规格

### 3.1 设备布局范围

| 设备范围 | 视口宽度 |
|---|---:|
| 手机端 | 320–430px |
| 平板端 | 600–899px |
| 桌面端 | 900px 以上 |

430–599px 属于需要覆盖的过渡宽度，不得遗漏测试。断点应结合实际布局需要设置，不得只为满足某个固定尺寸而硬编码。

### 3.2 基础视觉规格

| 项目 | 基准 |
|---|---:|
| 卡片圆角 | 12–16px |
| 卡片内边距 | 16–20px |
| 按钮高度 | 44–48px |

以上为设计基准，不是所有组件无条件采用的固定值。应根据页面密度、组件类型、内容和设备端合理调整，并保持同类组件一致。

## 4. 卡片与空间节奏专项验收

卡片间距是全站 UI 精修重点。每个页面至少检查以下六项：

1. **卡片之间**：同类卡片间距有规律，不拥挤、不松散；不同模块之间有清晰的分组层次。
2. **卡片内部**：标题、正文、辅助信息、图表和按钮之间留白合理，内容不会贴边或过度分散。
3. **同行卡片**：边缘、基线和视觉重心协调；同一网格中的卡片高度按内容和设计意图合理处理。
4. **不同行卡片**：纵向节奏稳定，模块间距有层级，不因内容长短产生明显的无序感。
5. **页面边缘**：左右留白与内容宽度协调，不浪费空间，也不让内容贴近屏幕边缘。
6. **响应式变化**：卡片随视口合理调整宽度、列数、内边距和间距，不出现参差、挤压或溢出。

不得为了形式统一而强制所有卡片等宽、等高；应优先保证内容层级、功能重要性和整体空间比例。

## 5. 正式测试视口

每轮相关页面验收应覆盖以下测试宽度：

| 设备/场景 | 视口宽度 |
|---|---:|
| 手机小屏 | 375px |
| 手机标准屏 | 390px |
| 手机大屏 | 430px |
| 平板 | 768px |
| 笔记本 | 1366px |
| 桌面显示器 | 1440px |
| 大屏显示器 | 1920px |

此外还必须测试 320px 手机端下限、430–599px 过渡区，以及各实际响应式断点前后。测试记录应注明实际使用的视口宽度和设备/浏览器环境。

## 6. 交易页面保护要求

交易页面视觉修改必须遵守以下约束：

- 保护现有交易核心逻辑和业务行为。
- 不擅自改变下单、撤单、订单确认及交易流程。
- 不破坏行情、盘口、余额、订单和交易数据的准确呈现。
- 允许优化卡片间距、布局比例、字体、颜色、对齐和视觉层次。
- 不得以视觉调整为由移除、隐藏或弱化必要的交易信息和风险提示。
- 涉及交易页面的修改后，必须回归测试关键交易操作及相关状态反馈。
- 若视觉改动可能影响交易操作，必须先验证交互行为，再判定是否可验收。

## 7. 多语言排版验收

七种语言均应进行实际页面检查，不得仅凭默认语言的截图推断其他语言合格。重点检查：

- 文案长度变化导致的换行、截断和溢出。
- 按钮、标签、导航和卡片标题的空间适配。
- 数字、货币、日期及交易术语的显示。
- 不同语言下组件高度、对齐和页面节奏。
- 手机端和电脑端各自的排版表现。

具体语言清单以 BTCBOX 项目当前支持的七种语言配置为准。

## 8. 页面验收状态

每个页面、每个验收维度应记录以下状态：

| 状态 | 定义 |
|---|---|
| 未检查 | 尚无实际检查记录或证据 |
| 检查中 | 正在执行检查 |
| 待修复 | 已发现间距、对齐、布局或适配问题 |
| 已修复待复测 | 修改已完成，但尚未完成复测 |
| 通过 | 对应维度的视觉、布局和响应式检查均合格 |
| 未通过 | 存在溢出、遮挡、布局错乱、可读性问题或操作受影响等缺陷 |

最终页面状态只有在四层验收全部通过，且适用的交易回归与多语言检查完成后，才可标记为“最终验收通过”。任何一层未通过或缺少证据，都不得宣布最终通过。

## 9. 必须保留的验收证据

每个页面应建立可追踪的验收记录，至少包括：

- 页面名称、路由或功能区域。
- 检查日期、版本/提交号及测试环境。
- 全站视觉一致性检查结果。
- 手机端独立检查结果及代表性截图。
- 电脑端独立检查结果及代表性截图。
- 连续响应式检查结果，注明视口宽度和断点。
- 发现的问题、严重程度和对应截图。
- 修复说明、关联提交及复测结果。
- 适用时的多语言排版和交易关键操作回归结果。

截图应能对应具体页面、视口尺寸和版本；不得使用设计稿或单纯代码规格代替实际运行页面的验收证据。

## 10. 执行流程

1. 开发或修改页面前，确认本规范及页面功能约束。
2. 实施页面和组件修改，优先复用统一设计规则。
3. 执行全站视觉一致性检查。
4. 独立执行手机端验收。
5. 独立执行电脑端验收。
6. 执行断点之间的连续响应式验收。
7. 执行适用的多语言排版检查。
8. 对交易页面执行关键交易操作回归。
9. 记录问题、修复、截图和复测结果。
10. 四层验收及适用专项检查全部通过后，才可标记最终完成。

## 11. 适用范围与规范维护

本规范适用于 BTCBOX 后续所有新页面开发、既有页面修改、重构、组件整合和发布前视觉验收。它是持续执行的项目标准，不是一次性检查清单。

如需调整断点、基础规格或验收规则，应更新本规范版本并记录变更原因；不得在单个页面中无记录地偏离标准。

---

**最终原则：功能正常只是基础。全站视觉一致性、手机端独立验收、电脑端独立验收和连续响应式验收必须同时通过，才算完成。**
